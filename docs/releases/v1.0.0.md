# WoonLens v1.0.0 Release Notes

WoonLens v1.0.0 is the first supported local Docker release of the guest-first,
privacy-conscious Dutch home-comparison application.

## Release Scope

The release provides live comparison of two to five Dutch addresses using
official data providers. Guest comparison requires no account. An optional OIDC
account can retain favourites and named comparison recipes, while provider
responses and generated comparison facts remain request-scoped and are not
stored by WoonLens.

The complete user-visible change list and known limitations are maintained in
the [changelog](../../CHANGELOG.md).

## Verification Record

The release candidate was verified on 2026-09-08 with the following gates:

- Backend formatting, Ruff linting, strict mypy checks, import-contract checks,
  and all 193 pytest tests passed with 90.45% coverage.
- Frontend formatting, ESLint, TypeScript checking, all 47 Vitest tests, and the
  Next.js production build passed.
- Both backend and frontend quality suites passed in their Linux Docker images.
- Both deterministic Chromium end-to-end smoke tests passed.
- The full Docker Compose stack started with healthy PostgreSQL, Redis, and
  Keycloak dependencies, and Alembic revision `20260902_03` applied.
- A real-browser guest smoke test completed live search and comparison with two
  public Rotterdam address records. The comparison displayed provider facts,
  provenance, retrieval context, and the expected degraded state for an
  unconfigured optional EP-Online key.
- A real-browser account smoke test completed OIDC sign-in and displayed
  owner-scoped favourites and saved comparisons.
- Tracked-file and high-confidence credential-pattern scans found no release
  secret, private key, local database, or raw data artifact.

## Data and Licensing Review

The data-source review was refreshed on 2026-09-08. WoonLens keeps PDOK license
interpretation dataset-specific, attributes CBS open data under CC BY 4.0,
keeps the EP-Online API key server-side and avoids prohibited bulk
redistribution, and treats Luchtmeetnet observations conservatively because no
blanket reuse license was identified. The detailed operational policy is in
[`DATA_LICENSING.md`](../DATA_LICENSING.md).

## Supported Release Boundary

This is a supported local Docker release, not a hosted production service. A
deployment operator remains responsible for production secrets, OIDC provider
selection, TLS and edge controls, backup and recovery, monitoring, source-term
review, and availability commitments.

## Publishing Procedure

1. Merge the release pull request into `main` after required checks pass.
2. Create the annotated tag `v1.0.0` from the verified merge commit.
3. Publish the GitHub release from that tag using this document and the
   changelog as the release notes.
4. Confirm the release page, source archives, and documentation links resolve.

The tag must not be created from the release branch before its pull request is
merged.
